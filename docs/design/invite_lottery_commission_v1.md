# Yuoyuo 邀请裂变 + 抽奖 + 返佣 V1 方案（修订版）

> 本文是对外部 PM 初稿的修订。修订依据是与现有代码库核对后的事实，以及三项产品决策：
> **(1) 返佣不提现现金，以独立「佣金（元）」站内储值展示，可等价买积分/会员/(未来)角色卡；(2) 剧情模式只摘前端入口，后端保留；(3) 防刷模型必须贴合"纯邮箱注册、无手机号无实名"的现状。**

## 0. 与现有代码的对齐结论（先读这段）

设计前先核对了 `backend/heart/invite/`、`core/config.py`、`billing/`、`routes_auth.py`。三条必须知道的事实：

## 1. 方案总结（产品负责人视角）

Yuoyuo V1 采用一条**全站内闭环、零现金流出**的增长链路：

```
邀请绑定 → 7 天内完成轻量有效对话 → 邀请人获得抽奖机会 → 新用户 30 天内付费
        → 邀请人获得 10% 返佣（记为「佣金（元）」储值）→ 可等价买积分/会员/(未来)角色卡
```

核心决策：

- **"发一句话"不算有效邀请**，升级为 **3 条主动消息 + 2 次有效 AI 回复 + 对话跨度 ≥ 2 分钟**。
- 普通 / 29 VIP / 69 VIP 每日抽奖上限 = **5 / 10 / 20**（69 VIP 不保留初稿的 40）。
- 抽奖机会可累计，有效期 30 天。所有用户同一奖池，不按等级改概率。
- 每次至少 20 币，即为保底；V1 不做复杂连续保底。
- **返佣不提现现金，作为独立「佣金（元）」储值。** 佣金按实付 10% 计、以**元**计价单独展示（用户看到"已赚 ¥6.9"的真实价值感），冻结 15 天后转为**可用佣金余额**。佣金余额可 1:1 等价购买积分、会员，以及（角色卡购买功能上线后）角色卡。这是本修订相对初稿最大的改动——砍掉现金提现，消除合规风险，同时保留真实钱感。
- 正常用户即时发奖；仅中高风险邀请延迟 / 冻结 / 审核。

**要替换的存量逻辑**：现有"首次聊天双方各 40 币 + 5/10 人里程碑"必须被抽奖机制替换，不能叠加。被邀请人仍保留全站统一的注册赠送 **40 币**（不是初稿写的 100），但不再有邀请固定奖。

## 2. 最终推荐业务规则

### 2.1 邀请绑定
- 邀请码在注册前由链接记录，或注册时填写；注册后最多 24h 内允许绑定，首次付费后不可补绑。
- 每个新用户只能绑定一个邀请人，绑定后不可改。
- 曾注销后恢复的账号、曾用相同支付身份付款过的历史账号，不算新用户。
- 邀请关系即使未达标也永久保留为"待转化"。

> 现状适配：绑定逻辑已存在于 `record_invite_signup`（`invite/service.py`），已处理 `self_invite` / `already_bound`。V1 只需在其上加"24h 时限"和"首付后不可补绑"两个约束。

### 2.2 有效邀请标准

被邀请人须在注册后 **7×24h 内**同时满足：

1. 完成邮箱验证 + 成年门禁。
2. 主动向至少一个 AI 角色发 **3 条**消息。
3. 至少收到 **2 次**完整、非报错、非安全拦截的 AI 回复。
4. 首末消息间隔 ≥ **120 秒**。
5. 三条消息合计 ≥ **15 个有效字符**，至少两条内容不同。
6. 纯表情、重复粘贴、撤回、接口报错不计入。
7. 通过设备 / 网络 / 账号关联风险检查（见 §6）。

低风险达标即时生效；中风险进最长 24h 待审；高风险不发奖进复核。

> **重要风险提示（初稿严重低估）**：当前纯邮箱注册下，"注册一个新邮箱"成本几乎为零。上面 1–6 条能挡脚本，**挡不住人肉多开邮箱刷抽奖**。因此 §3 的抽奖奖池**只发站内悠悠币 + 会员体验卡**（都无法变现），并对高价值奖品设库存和单用户封顶——即使被刷，损失下限也只是"站内货币发多了"，可控。若未来接入手机号/实名，可再放开。

### 2.3 抽奖次数

| 身份 | 每日上限 |
|---|---|
| 普通用户 | 5 |
| 29 元 VIP (plus) | 10 |
| 69 元 VIP (immersive) | 20 |

- 按有效邀请完成时间 + Asia/Shanghai 自然日计。
- 当日升级会员，当日总上限同步提升，已获次数计入新上限。
- 超上限的邀请仍记为有效、保留返佣资格，但不补发、不结转次日。
- 抽奖机会有效期 30 天，可累计，优先消耗最早到期的。
- 无终身邀请人数上限；> 500 有效邀请进"合作推广者"复核。

> 69 VIP 从 40 降到 20：40 次对应单账号日期望面值约 ¥151，V1 风控数据不足时窗口过大。连续 4 周异常邀请率 < 3% 且 ROI 达标后再灰度提高。

### 2.4 VIP 奖品履约（体验权益卡）

- 免费用户领取后可立即或 90 天内激活；已付费用户可在当前会员到期后激活。
- 不可转让、出售、兑换现金、转移账号。
- 体验期享对应功能 + 邀请次数上限。
- **不含正式会员的每日签到赠币（plus/immersive 80 币/天）、月度赠币、付费订单权益。** ← 成本红线，否则 3 天体验卡额外产生 240 币。

单用户中奖限制（近 N 天）：100 币 ≤ 2 次/30d；200 币 ≤ 1 次/30d；3 天 VIP 两档合计 ≤ 4 次/30d；1 个月 VIP 两档合计 ≤ 2 次/180d。命中受限时降级发 20 币，奖券同时消耗。

> 现状适配：会员卡发放复用 `afdian_sku_map` 的 `{"type":"membership","tier":"plus","days":3}` 结构，走现成的 membership grant 路径。体验卡需要一个 `membership_reward_coupons` 表记录"已领未激活"状态。

### 2.5 保底与会员奖池

V1 明确：**不做**连续 N 次保底、**不做**三套分级奖池、**不做**第 N 次进高级池、**不做**累计人数直接送大奖。理由：每次至少 20 币已是保底；会员激励通过更高次数上限体现，继续加会员中奖概率只会增加规则解释、概率校验、财务与公平性成本。Yuoyuo 是社交产品不是游戏。

### 2.6 返佣规则（**改为站内余额，不提现现金**）

- 比例：实付金额的 **10%**，按分记账 `floor(实付分 × 10%)`。
- 有效期：被邀请人注册后 **30 天**内的所有成功订单（会员 + 悠悠币充值）。
- 不限订单次数，仅算现金实付部分；优惠券 / 赠品 / 体验卡 / 佣金抵扣 / 免费订单不返。
- 被邀请人先付款后达标的，达标后可追溯生成该订单佣金。
- 邀请关系超抽奖上限仍可产生返佣。
- **结算形态：佣金冻结期满后，转为邀请人的「佣金余额」（以元记账）**，而非并入悠悠币钱包。佣金余额是独立的站内储值账户，单位为元，仅可用于站内消费：
  - **买会员**：1:1 抵扣（¥29 佣金买 29 元 plus，¥69 买 immersive），与现金定价一致，最自然。
  - **买积分（悠悠币）**：按站内充值汇率兑换（默认 1 元 = 10 币）。
  - **买角色卡**：角色卡购买功能上线后接入，同样 1:1 抵扣。
  - 记账建议：独立 `commission_ledger`（元/分为单位）记录佣金入账与消费，消费时生成对应的会员/积分/角色卡发放并写幂等键 `commission_spend:<order_id>`。**不直接写 `credit_transactions`**——佣金是"元储值"，悠悠币是"站内货币"，两者账户分离，消费时才转换。
  - **零现金流出、零提现合规问题**，同时用户看到的是真实的元价值。

> 不做永久返佣（形成不可控长期负债 + 多层推广预期）；只返首单又不足以激励关心新用户留存。30 天全订单最平衡。

### 2.7 佣金冻结与冲正（**无提现，只有冻结→入账**）

状态机：
```
待结算 →（T+15）→ 已入账（转入佣金余额，以元记账）
退款/拒付：待结算 → 已取消 ；已入账 → 反向扣减佣金余额（allow negative，后续佣金先补）
```

- 标准冻结：支付成功后 **15 个自然日**（覆盖退款窗口）。中风险订单延长至 30 天。
- 全额退款：全额冲正；部分退款按比例冲正。
- 若已入账后发生拒付：从佣金余额反向扣减；余额不足则记负，后续佣金先补齐。已消费掉的佣金（已买会员/积分）不追回，只让余额记负。
- **没有提现环节** → 初稿的提现上下限、每日/每月次数、人工审核、实名收款码、金额上限全部删除。这是本方案合规风险归零的关键。

### 2.8 后台配置与数据表

后台四个模块（原"提现审核"并入"返佣"，去掉打款相关）：
- **奖池管理**：活动版本、奖品类型、数量、权重、日库存、总库存、单用户限制、生效时间、兜底奖、启停。
- **邀请规则**：有效消息数、回复数、对话跨度、完成时限、各等级次数上限、机会有效期。
- **返佣规则**：比例、有效期、冻结期、中风险延长期、余额入账汇率。
- **风控中心**：规则分值、设备/IP 关联图、待审邀请、异常订单、佣金冻结、申诉。
- **预算监控**：奖池剩余、实际中奖分布、面值成本、预算使用率。

已发布奖池不可直接改；改概率必须发新版本；抽奖机会生成时绑定奖池版本。

建议数据表：
- 扩展 `user_invite_uses`：加资格计数、状态、达标时间、风险状态列。
- `invite_draw_chances`（机会获得/到期/消费账本）。
- `lottery_pool_versions` / `lottery_prizes` / `lottery_draws`。
- `membership_reward_coupons`（体验卡钱包）。
- `commission_entries`（佣金明细 + 冻结状态）+ `commission_ledger`（佣金余额账本，元/分为单位，入账与消费流水；**无 withdrawal 表**）。
- `referral_risk_events` / `admin_audit_logs`。

所有发奖、抽奖、返佣、冲正用唯一幂等键（复用 `grant()` 的 `idempotency_key`）；抽奖结果由服务端安全随机数 + DB 事务产生，前端只播动画。

## 3. 用户流程

- **邀请人**：进邀请页 → 看今日剩余次数 + 邀请码 → 分享 → 看好友"已注册/互动中/已生效/审核中" → 得抽奖机会 → 抽奖 → 看奖励 + 佣金余额。
- **被邀请人**：打开邀请链接 → 注册自动绑定 → 年龄验证 → 选角色 → 完成 ≥3 条真实互动 → 关系生效。全程不弹额外身份验证，只显示简短互动进度。
- **抽奖**：进抽奖页 → 看可用次数 + 最近到期 → 点抽 → 服务端原子扣一次机会并定结果 → 前端播转盘 → 币即时到账 / VIP 卡进权益钱包。同一 `chance_id` 重复请求返回同一结果。
- **返佣**：被邀请人付款 → 回调验签 → 订单幂等入库 → 校验有效邀请 + 30 天归因 → 生成待结算佣金（以元计） → T+15 转入邀请人佣金余额 → 退款自动冲正。
- **佣金消费**：邀请人在会员/充值/（未来）角色卡页看到"佣金余额 ¥X" → 结算时选择用佣金余额抵扣 → 1:1（会员/角色卡）或按汇率（积分）扣减佣金余额并发放权益。
- **~~提现~~**：**已删除。** 佣金是站内元储值，只进不出（现金），仅可站内消费。

## 4. 抽奖概率方案

成本口径：1 元 = 10 悠悠币；VIP 按面值折算。实际 API 边际成本通常更低。

| 奖品 | 概率 | 权重/10,000 | 单次成本 | 风险 |
|---|---|---|---|---|
| 20 币 | 50.00% | 5,000 | ¥2.00 | 低 |
| 40 币 | 28.00% | 2,800 | ¥4.00 | 低 |
| 60 币 | 10.00% | 1,000 | ¥6.00 | 低 |
| 80 币 | 5.00% | 500 | ¥8.00 | 中 |
| 100 币 | 3.00% | 300 | ¥10.00 | 中 |
| 200 币 | 1.00% | 100 | ¥20.00 | 高 |
| 29 VIP 3 天 | 1.50% | 150 | ¥2.90 | 中 |
| 69 VIP 3 天 | 1.00% | 100 | ¥6.90 | 中 |
| 29 VIP 1 个月 | 0.35% | 35 | ¥29.00 | 高 |
| 69 VIP 1 个月 | 0.15% | 15 | ¥69.00 | 很高 |
| **合计** | **100.00%** | **10,000** | | |

> 修正初稿笔误：初稿权重列 20 币写 5,800、40 币写 2,000，与百分比列（50%/28%）对不上，且合计 ≠ 10,000。此处按百分比重算为 5,000 / 2,800，合计校验 = 10,000。

普通悠悠币占 97%，100/200 币合计 4%，3 天卡合计 2.5%，月卡合计 0.5%。首期直接预留 10,000 张逻辑奖券（数量=权重），服务端随机排列逐张消费，该期最高面值负债可提前锁定。

## 5. 成本测算

**单次抽奖期望成本**：
- 悠悠币部分 = 20×50% + 40×28% + 60×10% + 80×5% + 100×3% + 200×1% = **34.2 币 = ¥3.42**
- VIP 部分 = 2.9×1.5% + 6.9×1% + 29×0.35% + 69×0.15% = **¥0.3175**
- 合计 = **¥3.7375 / 次**

> （初稿写 ¥3.7775，因其悠悠币部分误用 58% 权重；按修正后的 50% 概率表，正确值为 ¥3.7375。）

**各等级刷满每日上限的期望成本**：普通 5 次 ≈ ¥18.69；29 VIP 10 次 ≈ ¥37.38；69 VIP 20 次 ≈ ¥74.75。（初稿的 40 次方案 ≈ ¥149.50，已否决。）

**1,000 个有效邀请全部完成抽奖**：面值成本 ≈ **¥3,737.50**；按 85% 使用率 ≈ **¥3,176.88**。首期 10,000 次奖池面值上限 = 10,000 × ¥3.7375 = **¥37,375**。

预算控制：10,000 次为不可变更奖池版本；用量 70%/90% 预警；100% 停发新机会（邀请关系与返佣继续记录）；改概率必须发新版本；每周用真实 API 成本更新边际成本，面值成本作财务上限；实际分布偏离理论超统计容忍区间自动告警。

> 注：注册赠送 40 币是全站基础成本，不计入邀请增量。

## 6. 防刷方案（**重写：贴合纯邮箱注册现状**）

初稿依赖的"多手机号/实名支付身份"信号现在**不存在**。V1 实际可用信号：**设备指纹、IP、行为特征、（充值时才有的）支付账号**。风险分：低=即时通过，中=延迟 24h，高=冻结复核。分值不公开。

| 风险行为 | 检测方式（现状可落地） | 自动处理 | 人工审核 |
|---|---|---|---|
| 高｜多邮箱自邀 | 设备指纹 + IP + 注册时序聚类（无手机号可用） | 同设备/同指纹第 2 个后延迟发奖，达阈值冻结整组 | 家庭共用设备申诉 |
| 高｜同设备批量号 | 安装 ID / 设备特征；同设备 7 天注册 ≥3 | 延迟→冻结 | 合理场景放行 |
| 中｜同网络批量注册 | 同 IP 24h 注册 ≥5；代理/机房 IP；相同 UA | IP 单独不封，叠加其他信号才延迟 | 校园/公司白名单 |
| 高｜机械聊天刷达标 | 30s 内完成、内容重复、字符不足、无完整 AI 回复 | 不计有效对话 | 真实对话误判恢复 |
| 高｜脚本调接口 | 频率异常、固定间隔、缺正常页面会话、token 异常 | 限流、验证码升级、冻结机会 | 关联分析 |
| 高｜自充刷佣金 | 邀请双方相同支付身份；一支付工具付多个受邀号 | 佣金冻结 30 天，拦入账（**因无提现，无现金损失；且佣金只能站内消费**） | 家庭代付核验 |
| 高｜充值后退款 | 退款率、拒付、付后快速消费佣金余额 | 自动冲正；余额记负后续先补 | 大额/重复拒付处置 |
| 中高｜奖励套利 | VIP 卡转移、账号交易、多号共享设备 | 权益不可转让；高价值奖品延迟到账 | 核验实际使用 |
| 高｜团伙邀请 | 设备/IP/支付身份形成星型或环型图 | 冻结关联群组奖励与佣金 | 图谱复核 |

体验原则：单一信号（同 IP / 家庭网络 / 同设备）不直接判作弊；正常用户不需人脸/手机号/身份证；风险延迟期显示"奖励确认中"不暴露规则；拒奖保留原因码 + 证据快照 + 申诉入口；设备/网络特征只存哈希 + 必要期限。

> **因为砍掉了现金提现，防刷的最坏后果从"骗走真金白银"降为"多发了站内悠悠币"**，风控失败的代价大幅下降——这是选择余额闭环的核心收益。

## 7. 数据指标体系

### 邀请漏斗
邀请页曝光 → 分享行为 → 邀请链接访问 → 完成注册 → 有效对话 → 获得机会 → 完成抽奖 → 留存 → 付费。每层指标：UV/点击率（按等级拆）、复制/分享 UV、Landing UV、注册率/绑定率、有效邀请率/达标中位时长/7 天超时率、发放次数/上限未发次数/待审次数、抽奖使用率/机会过期率、D1/D3/D7 留存、首充率/首充时间/30 天 GMV。

### Dashboard 核心指标
邀请人数（去重绑定）、有效邀请率、每邀请用户成本（已发面值 ÷ 有效邀请）、被邀请用户 D1/D7 留存及与自然用户差异、首充率、ARPU/ARPPU、邀请 ROI（归因毛利 − 抽奖成本 − 已入账佣金 ÷ 激励总成本；**分母不再含提现成本**）、抽奖成本（面值 + 估算边际）、VIP 奖励数量（中奖/激活/过期）、**佣金余额**（待结算/已入账/已冲正，**无"已提现"**）、异常邀请率、抽奖分布偏差、奖池预算率、机会损耗率、退款拒付率。

支持按日期、会员等级、渠道、风险等级、奖池版本、注册批次筛选。

告警线：异常邀请率 > 5%；被邀请 D1/D7 比自然用户低 > 20%；实际单次面值偏离 ¥3.7375 > 10%；退款/拒付率 > 3%；高价值奖品库存 < 20%；单设备/单支付身份关联账号达高风险阈值。
