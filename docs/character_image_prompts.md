## 一、内存 / 尺寸铁律（务必先读，沿用探索页封面处理结论）

封面走的是「竖版立绘」通道，最终由 `scripts/seed_characters.py` 的 `_to_webp()` 处理：
**Pillow → WebP，等比缩放到 max-width 800，quality 80**，~2MB PNG 会被压到 ~100KB，
库里只存 S3 对象 + 短代理 URL（`/api/profile/cover-file/...`），**绝不 base64 内联进库**
（探索页 OOM 事故 commit `d3922fb` 就是全分辨率图片走内存代理，别重蹈覆辙）。

因此**生成阶段不要追求超高分辨率**：

| 项 | 建议值 | 理由 |
|---|---|---|
| 比例 | **2:3 竖版**（portrait） | 卡片 + 聊天背景都用竖版封面 |
| 出图尺寸 | **832×1248** 或 896×1344 | 已够清晰；反正会被下采样到宽 800 |
| 禁止 | 4K / 2048+ 大图 | 只会被压掉，还徒增出图与内存峰值 |
| 格式 | PNG 出图即可 | 导入时自动转 WebP，不用自己转 |
| 命名 | `<id>.png`（如 `pei_jue.png`） | 与 manifest 里 `cover:` 字段对齐 |

**回填封面到库**（出好图放进一个 `covers/` 目录后）：
```bash
cd backend
python3 scripts/seed_characters.py \
  --manifest scripts/seed_original_characters.yaml \
  --covers ./covers --force        # --force 刷新已存在角色的 cover_url
# batch2 同理换 manifest
```
> ✅ 已完成：两份 manifest 每个角色都补了 `cover: <id>.webp`；50 张原图已用
> `_to_webp`（800px/q80）转好放在 `~/Downloads/picture_webp/`（98.8MB → 3.4MB）。
> 部署时把该目录 rsync 到服务器，容器内跑 `seed_characters.py --covers <dir>` 落库+上传。
